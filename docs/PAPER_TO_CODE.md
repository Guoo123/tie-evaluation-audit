## BPC low-tie score: exact implementation identity

The archived value `0.1689 → 0.1685` is produced by the development score named
`po_group`, not by the simpler score named `sre`.

The implemented score can be written as follows. For item attribute `l`, first form an
item residual

```text
R[i,l] = A[i,l] - p_hat[i,l]
```

where `p_hat` is a three-fold out-of-fold masked-text logistic propensity, and set the
residual to zero where `p_hat > 0.95`. Then cross-fit an outcome control consisting of
a smoothed user mean and sparse user-by-item-group effects. The user score is

```text
S[u,l] = sum over training rows r for user u of
         (y[r] - user_oof[r] - group_oof[r]) * R[item[r],l].
```

Candidate score is `S[u] dot R[i]`.

The simpler item-only residual score is

```text
S_item_only[u,l] = sum y[r] * R[item[r],l].
```

It corresponds to the archived development name `sre` and had a materially larger tie
sensitivity. The artifact exposes both names. To make the manuscript implementation-
complete, describe the low-tie control as a **cross-fitted user/group outcome-
residualized score using item-side attribute residuals**, rather than as item-side
residualization alone.

## Archived versus recommended key policy

The submitted table's keyed values were generated by converting the 64-bit mixer to a
float32 key. The paper describes and acknowledges this archived implementation. The
artifact's `hardened_uint64` row retains the integer key and uses item ID as a final
collision fallback. It is the direct implementation of the paper's strict
row-permutation requirement.

## Exact BPC RawCount equation

The historical name `raw_count` is potentially misleading. The archived BPC pipeline
uses the scaled rating

```text
y_r = clip((rating_r - 1) / 4, 0, 1)
```

and computes

```text
U_raw[u,l] = sum_{r in training interactions of u} y_r * A[item_r,l]
score_raw(u,i) = U_raw[u] dot A[i].
```

Implementation: `src/tie_eval/bpc_models.py::build_score_matrices`, where `y` is the
weight passed to `aggregate_user_scores`. MovieLens RawCount, by contrast, is an
unweighted count over qualifying training interactions. The manuscript should not use
one ambiguous verbal definition for both domains.

## Camera-ready evidence boundary

`configs/paper.yaml` preserves the accepted-submission settings.
`configs/camera_ready.yaml` records the 100-seed analysis and corrected 0.39%
residualized-score tie rate. Compact final-table inputs live in
`results/camera_ready/amazon/`; the binary reconstructed rows and candidate-score
matrices are distributed through the companion release asset. See
`docs/CAMERA_READY_PROVENANCE.md`.
