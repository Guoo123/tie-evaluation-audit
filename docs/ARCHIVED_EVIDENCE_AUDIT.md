# Audit of the retained historical evidence

This package was built from a broad development ZIP rather than from a purpose-built
paper artifact. The audit below records what the ZIP proves, what it does not prove,
and how the new pipeline closes the gap prospectively.

## Evidence that was actually present

### Amazon Beauty & Personal Care

The ZIP retained the processed dataset counts, a resolved experiment configuration,
a run manifest, and an aggregate tie-audit summary. Those objects jointly support the
BPC dataset counts and the BPC rows reported in Table 2. The original frozen
candidate identities, candidate-level primary scores, and original tie-experiment
output directory were not present.

### MovieLens 25M + Tag Genome

The ZIP retained exact aggregate metrics by tie mode, an aggregate tie-audit summary,
and the main experiment summary with dataset counts. It did not retain candidate rows
or row-level tie arrays.

## Two discrepancies exposed rather than hidden

### 1. The BPC object called `RawCount` is rating weighted

The operational BPC implementation accumulates

```text
S_raw[u,l] = sum over training interactions r of
             clip((rating[r] - 1) / 4, 0, 1) * A[item[r],l].
```

The candidate score is `S_raw[u] dot A[i]`. It is therefore a rating-weighted
historical attribute total, not a literal unweighted event count. The artifact keeps
the historical code identifier `raw_count` for compatibility, but
`docs/PAPER_TO_CODE.md` states the exact equation. Manuscript wording should match the
operational quantity.

### 2. The MovieLens experiment summary and tie-audit CSV are separate runs

`results/archived/movielens/experiment_summary.json` contains hash-mode values that
are close to, but not identical with, the paired stable/hash values in
`tie_audit_summary.csv`. For example, RawCount hash NDCG@10 is 0.2336924146 in the
experiment summary and 0.2332344277 in the paired tie audit. The paper table uses the
paired tie-audit CSV, because that file contains stable and hash results generated by
the dedicated within-run comparison. The verifier treats the tie-audit CSV as the
canonical Table 2 source and uses the experiment summary only for dataset counts and
additional context.

## Low-tie control identity

The BPC paper row `0.1689 -> 0.1685` corresponds to the development score `po_group`:
item-side attribute residuals combined with a cross-fitted user-plus-group outcome
control. The simpler item-residual-only score (`sre`) was `0.2201 -> 0.1785` and had a
5.2% any-tie rate. The focused artifact exposes both as
`residualized_group_control` and `item_residual_only`.

## Prospective closure

Every new run writes a resolved configuration, runtime manifest, download manifest,
processed counts, frozen candidate rows, candidate score matrices, policy metrics,
diagnostics, and a SHA-256 run-integrity manifest. `scripts/replay_frozen.py` then
recomputes evaluator results without downloading, fitting, preprocessing, or
resampling.
